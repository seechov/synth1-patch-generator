## Детали по пунктам

### 1a. Раздельная обработка непрерывных и категориальных выходов ✅

**Проблема.** Общий `normalize()` масштабировал *все* признаки, включая
one-hot-кодированные категории, в `[-1, 1]`, а генератор заканчивался единым
`Tanh()`. Категориальные ветки «размывались», и модель не выдавала чистые
one-hot.

**Решение (реализовано).**
- `Generator` разделён на общий ствол + `cont_head` (`Tanh`) и
  `cat_heads` (`softmax` по каждой категориальной переменной).
- `normalize()` масштабирует только непрерывные колонки; one-hot остаются `0/1`.
- `engineer_features()` возвращает множество one-hot колонок.
- `save_normalization()` пишет `min`/`max` только для непрерывных признаков;
  `continuous_stats` и `categorical_encodings` явно разделены.
- Формат `normalization.json` и ONNX-интерфейс остались совместимыми с GUI.

---

### EMA генератора + экспорт EMA ✅

Накопить экспоненциальное скользящее среднее (EMA) весов генератора и
экспортировать в ONNX **EMA-версию**, а не последние веса. Сглаживает выбросы
качества при финальном экспорте.

**Задачи:**
- Завести EMA-копию `gen_ema` в `train()`.
- Обновлять после каждого шага генератора: `ema_avg = decay * ema_avg + (1 - decay) * weights`.
- Экспортировать EMA в `export_onnx()`.
- Сохранять EMA-веса в чекпоинт.

---

### Разный `lr` и нормализация/шум ✅

**Задачи:**
- Добавить `--lr-g` и `--lr-d` (ранее общий `--lr`).
- Опциональная спектральная нормализация дискриминатора
  (`torch.nn.utils.spectral_norm`), флаг `--spectral-norm`.
- Опциональный входной шум для дискриминатора (feature noise),
  флаг `--d-noise-std`. Уменьшает коллапс мод.

---

### Прогрессивный batch size и `latent_dim` ✅

**Задачи:**
- Батч = `min(batch_size, len(df) // 4)`, логировать предупреждение.
- Поднять дефолт `latent_dim` с `10` до `32` для разнообразия
  (уже параметризовано, изменить только дефолт).

---

### Train/val мониторинг и диагностика ✅

**Задачи:**
- Периодически считать метрику разнообразия (например, средняя L2-дистанция
  между сгенерированными и ближайшими реальными) для раннего выявления
  mode collapse.
- Логировать, сколько признаков/строк отброшено в `engineer_features()`.

## Контекст

- Входные данные — файлы `.sy1` (папка `presets/`), имена параметров в
  `COL_RENAME`, категориальные переменные в `CATEGORICAL_VARS`, отбрасываемые
  колонки в `TO_DROP`.
- GUI (`gui/src/main.rs`) читает `generator.onnx` + `normalization.json`;
  непрерывные параметры денормализуются из `[-1, 1]`, категориальные
  восстанавливаются через `argmax` по слайсу (`start_idx`, `num_classes`).
